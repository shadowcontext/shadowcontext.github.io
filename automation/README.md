# ShadowContext content automation

The `Hourly security briefing` GitHub Actions workflow runs at minute 17 of every hour. GitHub schedules are best-effort and may start later during periods of heavy demand.

## Publishing policy

Each run:

1. Reads recent entries from CISA advisories and KEV, Microsoft Security, Google Security, Google Cloud Threat Intelligence, Cloudflare, and Cisco Talos.
2. Searches GDELT's broad, multilingual news index for UAE cybersecurity reporting, including all seven emirates.
3. Prioritizes UAE records, then removes URLs already recorded in `_data/content_automation.json`.
4. Sends at most six new source records to the OpenAI Responses API.
5. Publishes at most one 550–850 word briefing when the records contain a coherent, defensively useful story.
6. Builds the Jekyll site before committing. A failed test or build is never pushed.

The model receives only feed titles, summaries, dates, publishers, and URLs. Source material is explicitly treated as untrusted input. The prompt forbids exploit instructions, invented claims, alarmism, and unattributed statistics. Source metadata is written by the script rather than generated by the model.

Runs with no new URLs make no changes. New but low-value items are marked as evaluated without creating an article, preventing repeated API calls for the same material. When an article is published, only cited URLs are marked as covered; unused candidates remain eligible for later runs.

No discovery service can literally guarantee visibility into every website. The combination of curated primary feeds and GDELT gives the automation broad coverage while the UAE-first queue makes local reporting the first editorial priority.

## Required repository configuration

Create an Actions secret named `OPENAI_API_KEY`:

1. Open the GitHub repository.
2. Go to **Settings → Secrets and variables → Actions**.
3. Add a repository secret named `OPENAI_API_KEY` containing a project-scoped OpenAI API key.

The workflow defaults to `gpt-5.6`. To select a different model without editing the workflow, add an Actions repository variable named `OPENAI_MODEL`.

The workflow also needs **Read and write permissions** for `GITHUB_TOKEN` under **Settings → Actions → General → Workflow permissions**. Repositories that enforce pull-request-only changes should replace the final push step with a pull-request workflow.

## Manual checks

Fetch and display candidates without calling OpenAI or writing state:

```sh
python -m pip install -r requirements-content.txt
python -m unittest discover -s automation -p 'test_*.py'
python automation/generate_content.py --dry-run
```

Trigger a live run from **Actions → Hourly security briefing → Run workflow** after the secret is configured.
